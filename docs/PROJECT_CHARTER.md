# 프로젝트 헌장

> 문서 상태: CURRENT
> 기준일: 2026-08-31
> 책임 역할: 제품 책임자

이 문서는 프로젝트가 해결하려는 문제, 현재 범위와 출시 판단 기준을 정의한다. 세부 게임 수치는 [게임 규칙](GAME_RULES.md)이 정본이다.

## 1. 제품 정의

Spot Difference Battle은 두 사람이 같은 원본·변경본 문제를 동시에 풀며 관찰력, 속도와 정확도를 겨루는 실시간 웹 게임이다.

핵심 가치는 다음 세 가지다.

- 설명 없이 이해되는 짧고 공정한 1대1 경쟁
- 데스크톱과 모바일에서 동일하게 신뢰할 수 있는 판정
- 검수·버전 관리된 문제를 지속적으로 추가할 수 있는 운영 구조

## 2. 대상 사용자와 사용 상황

- 설치 없이 짧은 캐주얼 대전을 원하는 사용자
- 같은 링크에서 PC 또는 휴대폰으로 친구·상대와 플레이하는 사용자
- 문제 품질, 신고와 경기 결과를 재현해야 하는 운영자

계정·랭킹·결제 없이 게스트 세션으로 핵심 대전의 재미와 기술적 공정성을 먼저 검증한다.

## 3. 현재 제품 단계

현재 단계는 **MVP 기능 완료 후 스테이징 안정화와 콘텐츠 확충 단계**다.

- 핵심 1대1 경기 흐름은 구현돼 있다.
- 활성 문제는 16세트지만 난이도별 풀은 EASY 11, NORMAL 6, HARD 3으로 불균형하다.
- 자동 타입·단위·통합·브라우저 테스트가 있으나 CI, 실제 운영 관측, 백업·복구 훈련과 정식 프로덕션 환경은 확립되지 않았다.
- 따라서 현재 문서에서 “배포 가능”은 로컬·스테이징 기술 배포를 뜻하며, 공개 서비스 출시 승인을 뜻하지 않는다.

## 4. MVP 범위

### 포함

- 게스트 닉네임과 같은 모드·난이도 기반 2인 매칭
- 준비, 문제 사전 로드, 서버 기준 카운트다운과 제한시간
- 검수된 원본·변경본 문제의 서버 권한 판정
- 플레이어별 독립 진행, 점수, 첫 완주·시간 종료·기권·생존전 결과
- 재접속 유예와 활성 경기 복구
- 모바일 반응형 배치, 동기화 확대·이동
- 완료·취소 경기 신고와 재현용 문제 버전 보존
- 메모리 저장소 및 선택적 PostgreSQL 저장소
- 단일 컨테이너 스테이징 배포

### 공개 출시 전 필수 보강

- 각 출시 난이도에서 한 경기 중 반복되지 않는 충분한 문제 수
- 모든 활성 문제의 모바일 육안 QA와 권리 증빙 승인
- CI에서 필수 품질 게이트 자동화
- 실제 PostgreSQL 백업·복원 및 재시작 복구 검증
- 운영 로그·지표·알림과 장애 대응 책임자 지정
- 지원 브라우저·기기·접근성 기준 검증
- 배포와 롤백 리허설

### 현재 비범위

- 계정, 랭킹, 시즌, 상점, 결제
- 친구 초대, 채팅, 관전, 리플레이
- 사용자 이미지 업로드와 경기 중 문제 제작
- 자동 제재와 완전한 운영자 신고 콘솔
- 여러 서버 인스턴스의 분산 매칭·실시간 상태

비범위 기능은 제품 책임자의 결정 기록 없이 구현하지 않는다.

## 5. 제품 원칙

1. **서버 권한**: 시간, 문제 순서, 정답, 점수와 승패는 서버가 결정한다.
2. **같은 조건**: 두 플레이어는 같은 문제 버전과 순서를 받는다.
3. **정답 비공개**: 경기 중 미발견 정답과 상대의 발견 위치를 노출하지 않는다.
4. **로드 공정성**: 이미지 로딩 지연이 경기 시간과 순위에 영향을 주지 않게 한다.
5. **재현 가능성**: 경기 결과와 신고는 당시 문제 버전·정답 영역으로 재현할 수 있어야 한다.
6. **콘텐츠 책임**: 활성 문제는 권리, 품질, 모바일 식별성과 문화적 적절성을 검수한다.
7. **작은 안전한 변경**: 규칙, 데이터와 배포 변경은 단계적이며 되돌릴 수 있어야 한다.

## 6. 성공 측정

다음 지표를 수집할 구조를 만든다. 공개 출시 목표값은 [검토 필요 항목](REVIEW_REQUIRED.md)에서 확정한다.

- 매칭 성공률과 매칭 대기시간
- 경기 시작 성공률, 완주율과 취소율
- 문제별 풀이 시간, 정답률, 오답률과 신고율
- 이미지 로드 실패율과 재접속 성공률
- 모바일·데스크톱 간 결과 차이
- 첫 경기 후 재대전·새 매칭 진입률
- 서버 오류율, 응답시간과 DB 복구 성공 여부
