# AI 협업 규칙

> 문서 상태: CURRENT
> 기준일: 2026-08-31
> 책임 역할: 기술 책임자

이 문서는 사람과 AI가 빠르게 구현하면서도 의도 손실, 문서 충돌과 검증 누락을 막기 위한 작업 계약이다. 저장소 수준의 필수 지침은 루트 `AGENTS.md`에도 요약돼 있다.

## 1. 바이브 코딩의 기본 계약

자연어 요청은 방향을 제시하지만 그 자체가 완전한 명세는 아니다. AI는 구현 전에 다음을 저장소 근거로 확정한다.

- 해결할 사용자 문제
- 포함 범위와 제외 범위
- 적용할 정본과 요구사항 ID
- 현재 코드·데이터·테스트의 실제 상태
- 예상 파일과 인터페이스 영향
- 위험도, 검증 방법과 롤백 방법
- 사람이 결정해야 하는 전제

작은 오탈자가 아니면 [변경 계약](templates/CHANGE_BRIEF.md)을 사용한다.

## 2. 필수 컨텍스트 순서

AI는 작업마다 필요한 만큼 아래 순서로 읽는다.

1. `AGENTS.md`
2. `docs/README.md`
3. `PROJECT_CHARTER.md`, `GAME_RULES.md`
4. `REVIEW_REQUIRED.md`
5. 변경 영역의 명세와 추적표
6. 실제 코드·테스트·Git 상태
7. 역사 기록은 원인 조사에 필요할 때만 읽음

과거 `CHANGES_*.md`의 설명을 현재 규칙으로 복원하지 않는다.

## 3. AI가 해서는 안 되는 추정

- 문서와 코드가 다를 때 최신 파일이 무조건 맞다고 추정
- 구현되지 않은 미래 항목을 현재 기능으로 표현
- 테스트 파일이 있다는 이유로 테스트가 통과했다고 표현
- `USER_SUPPLIED`를 법률 검증 완료로 해석
- 스테이징 배포 성공을 공개 출시 승인으로 해석
- 누락된 제품·보안·보존 정책을 일반적인 관행으로 임의 확정
- 사용자 요청 범위를 넘어 데이터 삭제, 배포 또는 외부 서비스 변경

불확실성이 결과를 바꾸면 조사 후 `REVIEW_REQUIRED.md`에 기록하고 사람에게 결정을 요청한다.

## 4. 구현 규칙

- 한 작업에 하나의 명확한 목표를 둔다.
- 변경 전 관련 테스트의 현재 결과를 확인하고, 변경 후 같은 범위와 신규 테스트를 실행한다.
- 규칙 변경은 `MVP_DECISIONS`의 결정과 `GAME_RULES`의 변경이 먼저다.
- 서버 권한 판정을 UI에 중복 구현하지 않는다.
- 공유 계약 변경은 소비자 전체를 검색한다.
- 저장 형식 변경은 구형 데이터 복구·격리·마이그레이션을 설계한다.
- 오류 경로, 시간 경계, 재시도, 중복 입력과 재접속을 정상 경로와 함께 구현한다.
- 코드 변경 없는 문서 감사에서도 사실을 코드·테스트·설정으로 검증한다.

## 5. 여러 AI 또는 사람의 병렬 작업

- 한 파일 또는 한 계약의 최종 책임자는 한 명만 둔다.
- 병렬 작업 전에 공통 정본, 인터페이스와 파일 소유 범위를 합의한다.
- 공유 타입·게임 코어·마이그레이션은 동시에 별도 수정하지 않는다.
- 다른 작업자의 미커밋 변경을 되돌리거나 정리하지 않는다.
- 충돌 해결자는 양쪽 의도를 읽고 테스트를 다시 실행한다.
- 인수인계는 [HANDOFF 템플릿](templates/HANDOFF.md)으로 남긴다.

## 6. 프롬프트에 포함할 최소 정보

좋은 작업 요청은 다음을 포함한다.

- 문제: 누가 어떤 상황에서 무엇을 못 하는가
- 기대 결과: 관찰 가능한 완료 상태
- 범위: 수정 가능한 영역과 건드리지 않을 영역
- 기준: 적용할 규칙·결정·요구사항 링크
- 제약: 호환성, 일정, 데이터, 디자인, 브라우저
- 검증: 반드시 통과할 시나리오
- 권한: 배포·삭제·외부 변경 허용 여부

정보가 빠져도 안전하게 조사 가능한 부분은 먼저 조사한다. 제품 의미를 바꾸는 누락은 추정하지 않는다.

## 7. 리뷰 체크

AI 산출물은 다음 질문으로 검토한다.

- 요청한 문제를 실제로 해결했는가?
- 정본과 모순되는 새 규칙을 만들지 않았는가?
- 실패·경계·동시성·복구 시나리오가 있는가?
- 정답, 개인정보, 비밀정보 또는 권리 위험이 추가됐는가?
- 테스트가 구현 세부가 아니라 사용자 결과를 검증하는가?
- 미검증 사항과 가정이 명확한가?
- 다른 작업자가 변경 이유와 롤백 방법을 이해할 수 있는가?

## 8. 완료 응답 형식

AI는 최종 응답에서 결과를 먼저 쓰고 다음을 구분한다.

1. 완료한 변경
2. 검증 결과와 정확한 명령
3. 미실행 또는 조건부 검증
4. 남은 위험과 사용자 결정 필요 사항
5. 관련 문서·파일 링크

“완벽”, “모두 검증” 같은 표현은 해당 범위와 증거를 함께 제시할 수 있을 때만 사용한다.
