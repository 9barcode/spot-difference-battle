# 2026-09-01 변경 요약 — 앱인토스 SDK 3 출시 준비

> 문서 상태: HISTORICAL

## 목적

앱인토스 게임 미니앱의 대표적인 가로형 저높이 viewport에서 원본과 변경본이 세로로 쌓여 플레이 영역이 화면 밖으로 밀리는 문제를 수정한다.

## 변경

- 높이 500px 이하 가로 화면에서 플레이 중 장식 헤더를 접고 상태바를 축소한다.
- 원본과 변경본을 844×390급 화면에서 좌우로 유지하고 남은 높이에 맞춰 정사각형 게임판을 축소한다.
- CSS 동적 viewport 단위와 Safe Area 환경 변수를 적용한다.
- 브라우저 핀치 줌을 비활성화하고 `viewport-fit=cover`를 적용한다. 게임 자체의 1~3배 확대 버튼은 유지한다.
- Chromium 2인 E2E의 한 플레이어를 844×390과 640×360으로 실행하고 두 게임판의 좌우 배치와 viewport 내부 표시를 검증한다.

## 검증

- `pnpm check`: 통과
- `pnpm test`: 79개 통과, PostgreSQL 실연동 2개는 테스트 DB가 없어 명시적으로 건너뜀
- `pnpm build`: UI와 서버 프로덕션 빌드 통과
- `pnpm e2e`: Chromium·Firefox·WebKit 9개 통과
- `pnpm audit --prod --audit-level high`: 알려진 취약점 없음
- `pnpm build:ait`: 미실행. 검증된 운영 `VITE_SERVER_URL`이 없고 기존 staging `/health`가 HTTP 404이므로 임의 주소로 산출물을 만들지 않음

## 앱인토스 출시 감사 추가 변경

- 공식 npm 최신 안정판 `@apps-in-toss/web-framework`·`@apps-in-toss/devtools` 3.1.1을 적용했다.
- SDK 3 형식의 `apps-in-toss.config.ts`로 전환하고 원격 main에서 확인한 변경 불가 appName `spot-difference-syk`를 사용한다.
- 앱인토스 빌드에서 운영 서버를 경로 없는 HTTPS origin으로 제한하고 서버는 라이브·QR origin allowlist를 지원한다.
- 공식 Safe Area 값을 구독하고 게임 내비게이션의 더보기·X 영역을 비운다. `Screen.setOrientation`으로 가로 방향을 설정하고 화면 종료 시 복구한다.
- 외부 Google Fonts를 제거하고 시스템 폰트로 바꿔 최초 화면의 외부 요청을 줄였다.
- 브라우저 기본 confirm 대신 키보드·스크린리더용 게임 내 기권 확인 모달과 서버 연결 재시도 UI를 추가했다.
- SDK의 많은 transitive 의존성 가운데 실행이 필요한 설치 스크립트만 허용하고, 사용하지 않는 권한은 빈 목록으로 유지했다.
- 라이브 CORS, HTTPS, URL·아이콘 검증과 640×360 Safe Area 회귀 테스트를 추가했다.
- GitHub Actions에서 check·test·build·Chromium E2E를 수행하는 CI를 추가했다.
- WebView 저장소 접근 실패를 격리하고 세로 화면의 페이지 스크롤을 복구하되 핀치 줌은 계속 차단했다.
- 프로덕션 의존성 감사에서 발견한 high 취약점 5건을 안전한 `fast-uri`·`find-my-way` 버전으로 갱신했다.
- 실제 규칙과 달랐던 구형 공개 승패 함수와 6개 `GAME_SCENE_ID` 계약을 제거하고 현재 16개 `GamePuzzleId` 계약으로 통일했다.
- [앱인토스 출시 기준](APPS_IN_TOSS_RELEASE.md)에 공식 심사 대조표, 환경값, 빌드, QR 실기기, 콘솔 제출물과 미해결 차단 조건을 기록했다.
