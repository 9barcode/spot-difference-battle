> 기준일: 2026-09-03

## 1. 시스템 구조

### 이해관계자와 관심사

| 이해관계자 | 주요 관심사 | 이 문서의 관점 |
|---|---|---|
| 플레이어 | 공정한 판정, 빠른 로드, 복구 가능한 경기 | 경기 계약, 웹·이미지 로드, 상태·동시성 |
| 제품·콘텐츠 책임자 | 규칙 일관성, 문제 품질, 재현성 | 권한과 정본, 문제 카탈로그 |
| 개발·QA 책임자 | 변경 영향, 테스트 가능성, 실패 격리 | 모듈 구조, 계약, 저장·복구 |
| 보안·개인정보 책임자 | 세션·정답·개인정보 보호 | 보안과 정보 공개, `SECURITY_PRIVACY` |
| 운영·앱인토스 검수자 | 배포, 관측, 롤백, 플랫폼 적합성 | 배포·확장 제약, 운영·출시 문서 |

### 시스템 경계

토스 WebView 또는 일반 브라우저의 웹 클라이언트가 HTTPS·Socket.IO로 단일 애플리케이션 서버와 통신한다. 서버는 선택적으로 PostgreSQL에 활성·완료 경기와 신고를 저장한다. 앱인토스 콘솔, 등급분류 기관, 모니터링·백업 공급자는 시스템 외부이며 해당 결과를 저장소 테스트가 대신할 수 없다.

- 웹 `UI/`: React·Vite, 원본/변경본 표시, 터치·포인터 좌표 변환, 이미지 사전 로드
- 서버 `apps/server/`: Fastify·Socket.IO, 게스트 세션, 매칭, 시간, 저장과 이벤트 검증
- 공유 `packages/shared/`: 문제 자산 매니페스트, 상태·이벤트 타입, 게임 모드·난이도 수치
- 게임 코어 `packages/game-core/`: 서버 권한 상태 전이, 정답·점수·승패 판정
- 저장소: PostgreSQL 구현과 로컬 메모리 구현
- 브라우저 검증 `e2e/`: 독립 브라우저 2개와 접근성·반응형 흐름

운영 빌드는 웹 정적 파일과 서버를 단일 Node.js 컨테이너·도메인에서 제공한다.

### 우선 품질 속성

1. 판정 무결성: 서버만 정답·점수·승패를 확정한다.
2. 공정성: 같은 문제·시작 조건을 보장하고 로드 지연을 경기 시간에서 제외한다.
3. 복구성: 중복·지연·재접속·손상 저장을 안전하게 처리한다.
4. 보안·비공개: 미발견 정답과 세션·개인정보를 최소 노출한다.
5. 검증 가능성: 요구사항에서 코드와 자동·수동 증거까지 추적한다.
6. 운영 가능성: 상태, 오류, 백업과 롤백을 측정·실행할 수 있어야 한다.

충돌 시 판정 무결성과 사용자 데이터 안전을 가용성보다 우선한다. 신뢰할 수 없는 경기 결과는 추정 복구하지 않고 `CANCELLED`로 종료한다.

## 2. 권한과 정본

- 제품 의도와 플레이 규칙: `PROJECT_CHARTER.md`, `GAME_RULES.md`
- 실행 수치와 공유 계약: `packages/shared/src/index.ts`
- 문제 파일 메타데이터: `packages/shared/src/puzzle-asset-manifest.ts`
- 정답 영역과 활성 문제 목록: `apps/server/src/game-puzzles.ts`
- 서버 권한 판정: `packages/game-core/src/match.ts`
- 웹 자산 연결: `UI/src/app/game-puzzles.ts`

서버가 문제 순서, 시간, 정답, 점수와 승패의 최종 권한이다. 클라이언트가 보낸 정답 여부·점수·문제 인덱스는 신뢰하지 않는다.

정본과 실행 코드가 다르면 어느 한쪽을 자동 우선하지 않고 출시 차단 결함으로 처리한다.

## 3. 문제 카탈로그

활성 경기는 버전 문제 쌍 카탈로그를 사용한다.

각 문제는 `pairId`, 버전, 원본·변경본 자산, 이미지 크기·SHA-256, 한 곳 이상의 검수된 정답 영역, 난이도, 권리 상태와 활성 상태를 가진다. 실제 정답 수는 문제별로 다를 수 있다. 정답 하나는 불규칙하거나 긴 객체 전체를 덮기 위해 여러 원형 영역을 가질 수 있으며, 모든 영역은 이미지 너비·높이 기준 `0~1` 정규화 좌표다.

공유 매니페스트, 서버 정답 목록과 웹 자산 목록은 테스트로 일치 여부를 확인한다. 이미지를 같은 이름으로 덮어쓰지 않고 버전·해시를 함께 변경한다.

## 4. 경기 계약

1. 클라이언트가 게스트 세션을 복구하거나 발급받는다.
2. 같은 모드·난이도의 두 플레이어가 매칭된다.
3. 서버가 난이도 등급과 `UNRATED` 문제로 같은 순서를 확정한다.
4. 양쪽이 첫 문제 ID와 에셋 버전을 포함해 로드 완료를 알린다.
5. 서버가 공통 카운트다운과 경기 마감 시각을 배포한다.
6. 위치 선택에는 경기 ID, 예상 상태·버전, 문제 인덱스, `pairId`와 정규화 좌표가 포함된다.
7. 서버가 정답·중복·오답·입력 잠금·생존 한도와 문제 완료를 판정한다.
8. 한 플레이어가 모든 문제를 완료하면 즉시 종료하고, 마감이면 총점·오답·무승부 순으로 판정한다.
9. 완료 결과를 저장한 뒤 활성 경기 상태를 정리하고 양쪽에 같은 최종 스냅샷을 보낸다.

## 5. 상태와 동시성

상태는 `READY → PRELOADING → COUNTDOWN → PLAYING → FINISHED`이며 신뢰할 수 없는 종료는 `CANCELLED`다. 로비와 매칭 상태는 클라이언트·서버 세션 흐름에 포함된다.

- 선택은 현재 상태, `pairId`, 문제 인덱스와 상태 버전이 맞아야 한다.
- 같은 `PLAYING` 상태의 동시 입력은 상대 진행으로 전역 버전이 변해도 서버 도착 순서로 판정한다.
- 동일 정답 중복 요청은 상태·오답을 바꾸지 않는다.
- 입력 잠금 중 요청, 마감 이후 요청과 비정상 속도 요청을 거절한다.
- 재접속은 서버 스냅샷을 기준으로 복구한다.

## 6. 웹과 이미지 로드

- 첫 문제 로드 완료 전 시간을 시작하지 않는다.
- 현재 문제를 푸는 동안 다음 문제의 두 이미지를 미리 불러온다.
- 다음 문제 로드 실패는 재시도를 제공하며, 공정성을 신뢰할 수 없으면 경기를 취소한다.
- 카운트다운 전에는 문제 내용을 시각적으로 가린다.
- 원본·변경본에 같은 1~3배 배율과 정규화 이동량을 적용한다.
- 포인터 이동이 6px을 넘으면 드래그로 분류해 정답 요청을 보내지 않는다.
- 선택 좌표는 실제 표시 이미지 경계를 기준으로 `0~1`에 다시 정규화한다.

## 7. 저장과 복구

활성 경기에는 스키마 버전, 설정, 문제 순서·버전·정답 영역, 상태·마감 시각과 플레이어별 진행·연결 상태를 저장한다.

완료 경기에는 문제 매니페스트, 승자·종료 사유, 양쪽 발견·오답·점수와 감사 정보를 보존한다. 신고는 완료 또는 취소 경기와 신고자를 검증하고 플레이어당 한 번만 저장한다.

마이그레이션은 `apps/server/migrations`의 번호순 SQL을 사용한다.

- 이미 적용된 마이그레이션 파일은 수정하지 않는다.
- 새 스키마는 전진 호환 추가를 우선한다.
- 버전이 없거나 손상된 구형 활성 경기는 경기별로 격리·삭제하고 정상 복구를 계속한다.
- 완료 저장이 성공하기 전에 활성 상태를 삭제하지 않는다.
- 실제 PostgreSQL 복구는 조건부 통합 테스트와 별도 백업·복원 훈련이 필요하다.

## 8. 보안과 정보 공개

- Socket.IO payload를 런타임 검증한다.
- 정답 영역은 서버 권한 데이터이며 경기 중 미발견 답을 보내지 않는다.
- 상대에게 문제 진행 수치만 보내고 정확한 발견 좌표와 오답·잠금 세부는 숨긴다.
- 입력 속도 제한, 상태·경기 소유권과 신고 권한을 검증한다.
- 개발 CORS는 명시 주소와 사설 LAN 개발 범위만 허용한다.
- 운영 로그는 추적 식별자와 안전한 오류 정보만 남기고 토큰·정답 전체·불필요한 개인정보를 제외한다.

## 9. 배포와 확장 제약

현재 컨테이너는 단일 서버 인스턴스를 전제로 메모리 매칭 큐와 실시간 경기 레지스트리를 사용한다. 여러 인스턴스로 확장하려면 매칭·세션·실시간 이벤트 상태를 Redis 같은 공유 계층으로 이동하고 순서·중복 처리 계약을 다시 검증해야 한다.

PostgreSQL이 설정되면 서버 시작 전에 마이그레이션을 실행한다. 환경, 관측, 백업과 롤백 기준은 `OPERATIONS.md`를 따른다.

## 10. 확인된 기술 부채

- 승패 판정은 서버 권위 `GameMatch` 내부 구현만 사용한다. 테스트 전용 구형 공개 판정 함수는 제거됐다.
- 문제 식별은 21개 매니페스트의 `GamePuzzleId`로 통일한다. 테스트 고정값은 `GAME_PUZZLE_ID`로만 주입한다.
- CI 워크플로, 운영 지표·알림, 부하 기준과 실제 백업·복원 자동화가 없다.

이 항목은 `REVIEW_REQUIRED.md`의 `REV-001`, `REV-002`, `REV-008`~`REV-010`에서 결정·추적한다.
