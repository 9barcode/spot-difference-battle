## 문제와 기대 결과

정본 구조는 있으나 변경 계약 사용, 검증 숫자, 권리 상태, 백로그와 해결 기록이 불일치한다. 모든 현재 문서가 하나의 권위 구조를 따르고, 앱인토스 승인에 필요한 외부 증거를 거짓 완료 없이 추적할 수 있어야 한다.

## 범위

- 문서 정보 구조, 표준 프로파일, 보안·개인정보 정본
- 검증 증거 단일화와 앱인토스 릴리스 체크리스트
- 역사 상태, 백로그, 권리 표현과 링크 정합화
- 문서 자동 감사

## 비범위

- 앱인토스 콘솔 제출·등급분류 취득
- 운영 서버·DB·대시보드 생성
- 법률·권리 승인과 실기기 검수의 대리 완료
- 게임 규칙과 코드 동작 변경

## 성공 조건

- 모든 내부 Markdown 링크가 유효하다.
- CURRENT·HISTORICAL·템플릿 상태가 명확하다.
- 검증 결과 숫자는 증거 원장 한 곳에서 관리한다.
- 해결된 검토 항목과 백로그가 일치한다.
- 활성 에셋 권리 상태와 문서 표현이 일치한다.
- 앱인토스 차단 항목은 증거·책임자·통과 조건을 가진다.
- 외부 미검증 항목은 `NOT_READY`로 유지한다.
