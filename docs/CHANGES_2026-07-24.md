# 변경 요약 — 소켓 이벤트 회귀 방지 (2026-07-24)

## 변경 내용

- 웹 클라이언트가 같은 경기에서 현재 버전과 같거나 오래된 `game:snapshot`을 무시하도록 했다.
- 새 경기의 스냅샷은 이전 경기보다 버전이 낮아도 정상적으로 수용하도록 경기 ID를 함께 비교한다.
- 새 매칭이 성사되면 이전 경기의 스냅샷 참조와 화면 상태를 즉시 초기화한다.
- 같은 상태 버전으로 중복 전송된 정답 요청이 `STALE_STATE`로 거부되고 오답 페널티를 만들지 않는 서버 통합 테스트를 추가했다.
- 네트워크 지연으로 버전 3 스냅샷이 버전 2보다 먼저 도착하는 순서를 가상 타이머로 재현해 최신 상태가 유지되는지 검증한다.
- 두 번의 정상 입력 뒤 늦게 도착한 과거 버전 정답 요청이 서버 상태를 변경하지 않는지 검증한다.
- 웹 패키지 테스트 명령을 추가해 루트 `pnpm test`에서 클라이언트 회귀 테스트도 실행한다.
- Playwright와 안정적인 UI 테스트 식별자를 추가했다.
- 서로 격리된 브라우저 두 개가 닉네임 설정, 매칭, 준비, 편집 진입, 기권 결과 동기화까지 수행하는 E2E 테스트를 추가했다.
- 1280×900 데스크톱과 390×844 모바일 브라우저가 같은 상대 위치를 클릭했을 때 정규화 좌표가 일치하는지 검증한다.
- Chromium·Firefox·WebKit 프로젝트를 구성해 전체 브라우저 E2E를 교차 실행한다.
- 닉네임 입력에 접근 가능한 이름을 추가하고 모든 주요 입력 요소에 고대비 키보드 포커스 테두리를 적용한다.
- 키보드만으로 닉네임 저장과 매칭 시작이 가능한지 검증한다.

## 검증 시나리오

- 첫 스냅샷 및 더 높은 버전 수용
- 같은 버전의 중복 스냅샷 무시
- 낮은 버전의 지연 스냅샷 무시
- 네트워크 지연으로 전달 순서가 역전돼도 최신 버전 유지
- 새 경기의 낮은 초기 버전 수용
- 두 상태 버전 뒤늦게 도착한 정답 요청 차단 및 오답 횟수 불변
- 두 브라우저가 같은 경기에 매칭되고 양쪽 모두 편집 화면에 진입
- 한쪽 기권 후 양쪽 브라우저에 패배·승리 결과가 서로 일치하게 표시
- 데스크톱·모바일 편집 보드의 클릭 좌표가 화면 크기와 픽셀 비율에 관계없이 동일하게 정규화
- 세 브라우저 엔진에서 키보드 포커스가 3px 실선으로 표시되고 Enter로 매칭 시작
