# 게임 장면 에셋 가이드

> 문서 상태: CURRENT
> 기준일: 2026-07-29

## 1. 현재 상태

장면은 서버가 선택한 `imageId`와 웹의 장면 카탈로그를 연결해 사용한다. 장면 정의에는 원본 이미지, 대체 텍스트, 객체 마스크, 자동 보충 후보와 라이선스 상태가 포함된다.

현재 등록:

| ID | 이름 | 파일 | 크기 | 라이선스 |
|---|---|---|---|---|
| `prototype-room` | 따뜻한 거실 | `UI/src/imports/image.png` | 1672×941, 약 3.28MB PNG | `UNVERIFIED`, Figma Make import |

현재 장면은 개발·게임 흐름 검증용이며 출시 승인 에셋이 아니다. 서버도 이 원본 한 장만 직접 읽어 제출 문제 이미지의 좌표를 검증한다.

## 2. 출시 장면 제출물

장면 하나당 다음을 준비한다.

- 제목·A/B 표시·테두리·워터마크가 없는 1920×1080 원본 PNG
- 실제 서비스 전송용 WebP 또는 AVIF
- 장면 이름과 고유 ID
- 선택 가능한 객체 15~18개의 이름과 마스크
- 자동 보충 후보
- 원작자, 생성 도구, 생성일, 이용 조건과 원본 증빙
- 서버 검증용 동일 버전 원본

현재 게임은 제작자가 원본을 수정하므로 미리 만든 B 이미지는 필요하지 않다.

## 3. 이미지 조건

- 정확한 16:9 비율
- 모바일에서도 식별 가능한 크기의 객체
- 객체가 화면 끝에서 잘리거나 심하게 겹치지 않음
- 읽을 수 있는 글자·숫자·상표·워터마크 없음
- 색상만으로 구분해야 하는 차이에 의존하지 않음
- 전경 객체가 배경 객체의 선택 영역에 가려지지 않음
- 효과 적용 시 제외 마스크와 객체 경계가 유지됨

## 4. 등록 절차

1. 출처와 이용 조건을 확인하고 라이선스 기록을 만든다.
2. `packages/shared/src/index.ts`의 `GAME_SCENE_IDS`에 ID를 추가한다.
3. 웹 원본·최적화 이미지와 객체 마스크를 등록한다.
4. `UI/src/app/game-scenes.ts`에 장면·객체·후보·라이선스를 등록한다.
5. 서버가 같은 `imageId`의 원본과 허용 객체·효과를 읽도록 장면별 서버 카탈로그를 등록한다.
6. PC·모바일에서 모든 객체의 선택과 효과 경계를 육안 검수한다.
7. 단위·서버 통합·브라우저 E2E를 실행한다.
8. 모든 조건을 통과한 뒤 `licenseStatus`를 `VERIFIED`로 바꾼다.

공유 ID와 웹 카탈로그만 추가해서는 완료가 아니다. 현재 서버는 단일 원본을 검증하므로 5단계가 구현되기 전 두 번째 장면을 실제 매칭에 노출하면 안 된다.

## 5. 완료 조건

- 서버 선택 장면이 저장·재접속·재시작 후 유지된다.
- 양쪽이 같은 장면 버전을 사용한다.
- 서버가 해당 장면 원본으로 문제 이미지와 정답 좌표를 검증한다.
- 서버가 등록되지 않은 객체·중복 객체·허용되지 않은 효과를 거절한다.
- 모든 자동 보충 후보가 유효한 객체다.
- 모든 객체를 모바일에서 독립 선택할 수 있다.
- 원본과 서비스 파일의 해시 또는 버전을 추적할 수 있다.
- 라이선스가 `VERIFIED`다.
- 신고 조사 기간 동안 필요한 문제 이미지와 정답 정보를 재확인할 수 있다.

## 6. 출시 목표

검증된 장면 10개를 준비하고 경기마다 서버가 등록 장면 중 하나를 선택한다. 현재 카탈로그 기반은 이 목표를 위한 토대이며 콘텐츠 완료를 의미하지 않는다.
