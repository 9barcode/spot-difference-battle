# 게임 문제 에셋 가이드

> 문서 상태: CURRENT
> 기준일: 2026-08-04

## 1. 에셋 모델

게임 콘텐츠 단위는 단일 장면이 아니라 `원본 + 변경본 + 정답 3곳`으로 구성된 문제 쌍이다. 경기 중 플레이어가 이미지를 수정하지 않는다.

문제마다 다음을 준비한다.

- 고유 `pairId`와 버전
- 원본 PNG와 서비스용 WebP 또는 AVIF
- 변경본 PNG와 서비스용 WebP 또는 AVIF
- 정확히 3개의 정답 ID·이름·정규화 영역
- 이미지 크기·해시와 난이도
- 원작자, 생성 도구, 생성일, 이용 조건과 원본 증빙
- 모바일 육안 검수 결과와 활성 상태

## 2. 현재 보유 상태

| 장면 | 원본 | 변경본 | 문제 사용 상태 |
|---|---|---|---|
| 마법의 버섯 숲 | 있음 | 있음 | 정답 3곳 등록 완료, 플레이 난이도 검수 필요 |
| 바닷속 보물 | 있음 | 있음 | 정답 3곳 등록 완료, 플레이 난이도 검수 필요 |
| 아늑한 카페 | 있음 | 유효한 별도 파일 없음 | 변경본 필요 |
| 사이버 도시 | 있음 | 유효한 별도 파일 없음 | 변경본 필요 |
| 카툰 연구실 | 있음 | 없음 | 변경본 필요 |
| 따뜻한 거실 | 있음 | 없음 | 라이선스 미확인, 출시 제외 |

카페와 도시의 이전 original/modified 제공 파일은 각각 SHA-256까지 동일해 차이가 없었다. 숲과 바다의 변경 기준본은 원본과 다르지만 생성형 편집 영향으로 전체 캔버스에 미세 픽셀 변화가 퍼져 있다. 따라서 픽셀 차이 자동 추출이 아니라 의도한 3곳을 수동 정답 영역으로 등록한다.

현재 `장면 6개`는 `플레이 가능한 문제 6세트`를 뜻하지 않는다. 현재 온라인 테스트에는 숲과 바다 2세트가 등록돼 있다. 실제 사용자 플레이를 통한 경계·난이도 조정은 남아 있다.

## 3. 이미지 조건

- 원본과 변경본의 크기·비율·구도·크롭이 같음
- 제목, A/B 표시, 테두리, 상표와 워터마크 없음
- 의도한 차이는 정확히 3곳
- 영역 밖 화풍·조명·노이즈 변화 최소화
- 모바일에서 확대했을 때 독립적으로 식별 가능한 크기
- 색상만 구별해야 하는 문제에 의존하지 않음
- 정답 영역이 겹치지 않고 화면 가장자리에서 잘리지 않음

정사각형 1024×1024 이미지는 플레이 검증에 사용할 수 있다. 출시 해상도·비율은 실제 모바일 레이아웃 검증 후 확정하며, 기존 16:9 단일 장면 조건을 문제 쌍에 기계적으로 강제하지 않는다.

## 4. 등록 절차

1. 출처와 이용 조건을 확인한다.
2. 원본·변경본에 안정적인 ID와 버전을 부여한다.
3. 두 이미지의 크기·크롭과 해시를 확인한다.
4. 제작자가 의도한 차이 3곳을 이름과 정규화 영역으로 등록한다.
5. PC·모바일에서 정답과 오답 경계를 육안 검수한다.
6. 서버 문제 카탈로그와 웹 자산 카탈로그를 함께 등록한다.
7. 단위·서버·브라우저 테스트를 실행한다.
8. 플레이 데이터로 난이도와 오답률을 확인한 뒤 활성화한다.

파일 순서나 업로드 순서로 original/modified를 추측하지 않는다. 카탈로그의 명시적 `originalImage`와 `modifiedImage` 필드를 사용한다.

## 5. 수량 목표

- 기능 개발과 내부 테스트: 검증된 5세트 이상
- 3분 경기: 같은 경기에서 반복되지 않는 10세트 이상
- 초기 반복 서비스: 난이도를 섞은 20~30세트 이상

## 6. 완료 조건

- 양쪽이 같은 문제 순서와 파일 버전을 사용한다.
- 현재·다음 문제를 경기 시간 손실 없이 불러온다.
- 정답이 정확히 3개이며 영역 밖 미세 변화는 판정하지 않는다.
- 모바일·데스크톱에서 같은 정규화 좌표가 같은 답이다.
- 라이선스가 확인되고 문제 버전을 재현할 수 있다.
- 신고 조사 기간 동안 이미지·정답·경기 사용 버전을 보존한다.
