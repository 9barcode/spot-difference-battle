# 게임 장면 에셋 가이드

> 문서 상태: CURRENT
> 기준일: 2026-08-02

## 1. 현재 상태

장면은 서버가 선택한 `imageId`와 웹의 장면 카탈로그를 연결해 사용한다. 장면 정의에는 원본 이미지, 대체 텍스트, 객체 마스크, 자동 보충 후보와 라이선스 상태가 포함된다.

현재 등록:

| ID | 이름 | 파일 | 크기 | 라이선스 |
|---|---|---|---|---|
| `prototype-room` | 따뜻한 거실 | `UI/src/imports/image.png` | 1672×941, 약 3.28MB PNG | `UNVERIFIED`, Figma Make import |
| `cartoon-laboratory` | 카툰 연구실 | `laboratory-1920.png` + 무손실 WebP·AVIF | 1920×1080 | `VERIFIED`, 제작자 본인의 프로젝트 사용 허가 |
| `cozy-cafe` | 아늑한 카페 | `cozy-cafe.png` + 무손실 WebP | 1024×1024 | `VERIFIED`, 제작자 본인의 프로젝트 사용 허가 |
| `enchanted-forest` | 마법의 버섯 숲 | `enchanted-forest.png` + 무손실 WebP | 1024×1024 | `VERIFIED`, 제작자 본인의 프로젝트 사용 허가 |
| `cyber-city` | 비 오는 사이버 도시 | `cyber-city.png` + 무손실 WebP | 1024×1024 | `VERIFIED`, 제작자 본인의 프로젝트 사용 허가 |
| `underwater-treasure` | 바닷속 보물 | `underwater-treasure.png` + 무손실 WebP | 1024×1024 | `VERIFIED`, 제작자 본인의 프로젝트 사용 허가 |

`prototype-room`은 개발·게임 흐름 검증용 미확인 에셋이다. `cartoon-laboratory`는 제공자가 직접 제작했고 상업적 사용·수정·배포를 포함한 프로젝트 사용을 허가했다고 2026-07-31 확인해 라이선스 상태가 `VERIFIED`다. 2026-08-02에 1920×1080 PNG 정본과 픽셀이 동일한 무손실 WebP·AVIF를 생성했다. 웹은 WebP를 사용하고 서버는 PNG 정본으로 제출 문제 이미지의 좌표를 검증한다. 내부 검수에서는 `GAME_SCENE_ID=cartoon-laboratory`처럼 특정 장면을 고정할 수 있다.

2026-08-02 제공된 카페·마법 숲·사이버 도시·바닷속 보물은 제작자가 직접 만든 1024×1024 장면이다. 각 장면에 15개 객체 마스크와 무손실 WebP를 등록했으며 PNG는 서버 원본, WebP는 웹 전송본으로 사용한다. 제공된 카페와 도시의 modified/original 파일은 바이트까지 동일해 별도 수정 기준본을 보관하지 않았다. 숲과 바다는 서로 다른 수정 기준본을 QA 참고 파일로 보관한다. 네 장면은 플레이 가능하지만 16:9 출시 제출물 조건은 아직 충족하지 않는다.

## 2. 출시 장면 제출물

장면 하나당 다음을 준비한다.

- 제목·A/B 표시·테두리·워터마크가 없는 1920×1080 원본 PNG
- 실제 서비스 전송용 WebP 또는 AVIF
- 장면 이름과 고유 ID
- 선택 가능한 객체 15~18개의 이름과 마스크
- 자동 보충 후보
- 원작자, 생성 도구, 생성일, 이용 조건과 원본 증빙
- 서버 검증용 동일 버전 원본

현재 게임은 제작자가 원본을 수정하므로 미리 만든 B 이미지는 필요하지 않다.

## 3. 이미지 조건

- 정확한 16:9 비율
- 모바일에서도 식별 가능한 크기의 객체
- 객체가 화면 끝에서 잘리거나 심하게 겹치지 않음
- 읽을 수 있는 글자·숫자·상표·워터마크 없음
- 색상만으로 구분해야 하는 차이에 의존하지 않음
- 전경 객체가 배경 객체의 선택 영역에 가려지지 않음
- 효과 적용 시 제외 마스크와 객체 경계가 유지됨

## 4. 등록 절차

1. 출처와 이용 조건을 확인하고 라이선스 기록을 만든다.
2. `packages/shared/src/index.ts`의 `GAME_SCENE_IDS`에 ID를 추가한다.
3. 웹 원본·최적화 이미지와 객체 마스크를 등록한다.
4. `UI/src/app/game-scenes.ts`에 장면·객체·후보·라이선스를 등록한다.
5. 서버가 같은 `imageId`의 원본과 허용 객체·효과를 읽도록 장면별 서버 카탈로그를 등록한다.
6. PC·모바일에서 모든 객체의 선택과 효과 경계를 육안 검수한다.
7. 단위·서버 통합·브라우저 E2E를 실행한다.
8. 원작자와 사용 허가가 확인되면 `licenseStatus`를 `VERIFIED`로 바꾼다.
9. 해상도·포맷·마스크·테스트 등 나머지 출시 조건은 라이선스 상태와 별도로 모두 확인한다.

공유 ID, 웹 카탈로그와 서버 원본·허용 객체 카탈로그를 한 변경에서 함께 등록해야 한다. 타입 검사와 카탈로그 테스트는 세 목록 중 하나가 빠지거나 객체 ID가 다르면 실패한다.

## 5. 완료 조건

- 서버 선택 장면이 저장·재접속·재시작 후 유지된다.
- 양쪽이 같은 장면 버전을 사용한다.
- 서버가 해당 장면 원본으로 문제 이미지와 정답 좌표를 검증한다.
- 서버가 등록되지 않은 객체·중복 객체·허용되지 않은 효과를 거절한다.
- 모든 자동 보충 후보가 유효한 객체다.
- 모든 객체를 모바일에서 독립 선택할 수 있다.
- 원본과 서비스 파일의 해시 또는 버전을 추적할 수 있다.
- 라이선스가 `VERIFIED`다.
- 신고 조사 기간 동안 필요한 문제 이미지와 정답 정보를 재확인할 수 있다.

## 6. 출시 목표

검증된 장면 10개를 준비하고 경기마다 서버가 등록 장면 중 하나를 선택한다. 현재 서버는 6개 후보 장면 중 하나를 무작위 선택한다. 연구실은 라이선스·해상도·전송 포맷 조건을 충족했다. 새 정사각형 장면 4개는 라이선스와 전송 포맷은 확인됐지만 16:9 정본과 최종 마스크 육안 검수가 남았고, 거실은 여전히 `UNVERIFIED`다.
