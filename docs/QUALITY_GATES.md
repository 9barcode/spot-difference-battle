# 품질 게이트

> 문서 상태: CURRENT
> 기준일: 2026-09-04
> 책임 역할: QA 책임자와 기술 책임자

품질 게이트는 변경이 다음 단계로 넘어갈 수 있는 최소 증거다. 테스트를 실행하지 못했으면 면제된 것이 아니라 미검증 위험으로 남는다.

## 1. 공통 진입 조건

구현을 시작하기 전에 다음이 있어야 한다.

- 문제·기대 결과·범위·비범위가 적힌 변경 계약
- 적용할 정본과 요구사항 ID
- 위험도와 승인 필요 여부
- 테스트, 데이터 마이그레이션과 롤백 계획
- 해결되지 않은 제품 결정이 없음

## 2. 공통 병합 조건

- 정본, 파생 문서, 코드와 테스트가 같은 동작을 설명한다.
- 차단 결함이 없다.
- 새 동작과 중요한 실패 경로에 자동 테스트가 있다.
- 실행한 명령, 결과, 미실행 검증이 기록돼 있다.
- 실행 증거가 `VERIFICATION_EVIDENCE.md`와 해당 릴리스 체크리스트에 연결돼 있다.
- 비밀정보·개인정보·정답 전체가 로그나 클라이언트에 새로 노출되지 않는다.
- 데이터·라이선스·접근성·운영 영향이 검토됐다.
- 되돌리기 또는 안전한 비활성화 경로가 있다.

## 3. 변경 유형별 필수 검증

| 변경 | 필수 자동 검증 | 추가 수동·환경 검증 |
|---|---|---|
| 문서만 변경 | Markdown 링크·상태·정본 중복 검사 | 관련 코드와 사실 대조 |
| 공유 타입·게임 코어 | `pnpm check`, `pnpm test`, `pnpm build` | 경계시간·동시 입력·복구 리뷰 |
| 서버·소켓 | 기본 세트 + 서버 통합 테스트 | 두 클라이언트, 재접속, 오류·종료 흐름 |
| UI·흐름 | 기본 세트 + 관련 Playwright | 데스크톱·모바일, 키보드, 스크린리더 |
| 게임 규칙·점수 | 전체 단위·통합·3브라우저 E2E | 제품 승인, 양쪽 결과와 정답 비공개 |
| DB·마이그레이션 | 기본 세트 + 실제 PostgreSQL 통합 테스트 | 백업·복원, 구·신버전 호환, 롤백 리허설 |
| 문제 에셋 | 매니페스트·파일·좌표 테스트 + E2E | PC·모바일 육안 QA, 권리 승인 |
| 배포·인프라 | 프로덕션 빌드, Docker 빌드, `/health` | 스테이징 스모크, 관측, 롤백 리허설 |
| 보안·개인정보 | 관련 테스트와 의존성 감사 | 위협 모델, 로그·보존·권한 검토 |

기본 세트:

```powershell
pnpm check
pnpm test
pnpm build
```

브라우저 흐름:

```powershell
pnpm e2e
```

PostgreSQL 조건부 테스트는 `DATABASE_URL`을 실제 테스트 DB로 지정한 상태에서 실행한다. 운영 DB를 테스트에 사용하지 않는다.

## 4. 핵심 게임 회귀 게이트

다음은 변경 영역과 무관해 보여도 규칙·상태·공유 계약 변경 시 반드시 검증한다.

- 같은 모드·난이도의 두 플레이어만 매칭됨
- 같은 문제 순서와 에셋 버전
- 양쪽 로드 후 서버 시각 동시 시작
- 플레이어별 독립 진행과 다음 문제 이동
- 정답·중복·오답·난이도 잠금 판정
- 첫 전체 완주 즉시 종료
- 시간 종료 시 총점, 오답, 무승부 판정
- 생존전 오답 한도, 기권, 재접속 유예와 취소
- 상대 정답 위치와 미래 문제 정답 비공개
- 모바일 확대·드래그 후 정규화 좌표
- 완료 경기 저장, 감사 데이터와 신고 중복 차단

## 5. 비기능 게이트

### 보안과 개인정보

- 클라이언트 입력은 런타임 검증한다.
- 정답과 점수는 서버가 계산한다.
- 로그에는 토큰, 원본 요청 전체, 정답 목록과 불필요한 개인정보를 남기지 않는다.
- 의존성 취약점과 비밀정보 포함 여부를 출시 전에 검사한다.

### 접근성

- 모든 조작에 키보드 포커스와 접근 가능한 이름이 있다.
- 색상만으로 성공·실패·잠금을 전달하지 않는다.
- 모바일 터치 목표, 확대와 드래그가 답 선택과 충돌하지 않는다.
- 지원 스크린리더와 색각 기준은 공개 출시 전에 확정한다.

### 성능과 안정성

- 첫·다음 문제 선로딩 실패가 공정성을 훼손하지 않는다.
- 이미지 크기와 번들 변화가 기록된다.
- 재접속과 서버 재시작 후 상태가 복원되거나 명확히 취소된다.
- 목표 응답시간·동시 접속자·오류율은 공개 출시 전에 확정하고 부하 검증한다.

## 6. 결함 등급

| 등급 | 정의 | 처리 |
|---|---|---|
| 치명적 | 잘못된 승패, 정답 노출, 데이터 손실, 보안 침해, 서비스 전면 불가 | 즉시 출시 중단·롤백 |
| 높음 | 시간·점수·복구·매칭·로드 공정성 오류, 주요 기기 진행 불가 | 병합·출시 차단 |
| 보통 | 우회 가능한 기능·접근성·운영 문제 | 책임자와 해결 시점 지정 |
| 낮음 | 결과에 영향 없는 표현·시각 문제 | 백로그 등록 가능 |

## 7. 스테이징 게이트

- 기본 세트와 관련 E2E 통과
- DB 변경 시 실제 PostgreSQL 테스트 통과
- 빌드 이미지 기동과 `/health` 정상
- PC·모바일 2인 경기 1회 이상 완주
- 재접속 또는 기권, 신고, 롤백 경로 확인
- 알려진 치명적·높음 결함 0개

## 8. 공개 출시 게이트

스테이징 게이트에 더해 다음이 필요하다.

- `REVIEW_REQUIRED.md`의 출시 차단 항목 해소
- CI에서 필수 검증 자동 실행 및 보호 규칙 적용
- 난이도별 콘텐츠 수량·권리·육안 QA 승인
- 백업·복원과 롤백 리허설 성공
- 로그·지표·알림·온콜 책임자와 중단 기준 확정
- 개인정보·보존·이용정책 검토
- 지원 브라우저·기기·접근성 매트릭스 통과
- 보안·개인정보 게이트와 앱인토스 운영·기능·디자인·보안 검수 자료 준비
- 출시 책임자의 서면 승인

현재 저장소는 이 공개 출시 게이트를 충족하지 않는다.
