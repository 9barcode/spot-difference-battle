# 화면 명세

> 문서 상태: CURRENT
> 기준일: 2026-08-31
> 책임 역할: 제품·UX 책임자
> 게임 동작은 `GAME_RULES.md`, 구현 완료 여부는 `UI_AUDIT.md`를 따른다.

## 공통 원칙

- 원본과 변경본을 명확하게 표기한다.
- 정답·오답·잠금은 색상뿐 아니라 문구와 형태로 알린다.
- 터치 대상은 모바일 최소 크기를 확보한다.
- 확대·이동 동작과 정답 선택을 구분한다.
- 남은 시간, 현재 문제와 `찾은 수/실제 차이 수`는 항상 확인 가능해야 한다.
- 연결·로드·서버 오류에는 사용자가 할 수 있는 다음 행동을 제공한다.

## 로비와 매칭

- 닉네임 입력·저장
- 기본전·속도전·생존전 선택
- 쉬움·보통·어려움 선택과 간단한 차이 설명
- 빠른 대전
- 매칭 대기와 취소
- 상대 매칭 완료와 준비 버튼

제작자/찾는 사람 역할 표시는 제거한다. 양쪽 모두 같은 목표 안내를 본다.

## 사전 로드와 카운트다운

- 양쪽 준비 상태
- 이미지 로딩 진행과 실패 안내
- 수동 재시도와 취소 경로
- 로드 완료 후 가려진 게임 보드
- 서버 기준 3초 카운트다운

카운트다운 전에 이미지 내용을 노출하지 않는다.

## 경기 화면

필수 요소:

- 원본 이미지
- 변경본 이미지와 선택 입력
- 남은 경기 시간
- 내 현재 문제와 `찾은 수/실제 차이 수`
- 상대 현재 문제와 `찾은 수/실제 차이 수`
- 내 오답 수와 입력 잠금 피드백
- 콤보와 현재 문제 번호
- 나가기

현재 문제의 차이를 모두 찾으면 짧은 완료 피드백 후 다음 문제로 자동 전환한다. 상대의 정답 위치·오답·잠금은 표시하지 않는다.

데스크톱과 높이 500px 이하의 가로형 게임 WebView는 두 이미지를 좌우 배치하고, 세로형 모바일은 상하 배치를 사용한다. 가로형 게임 WebView에서는 플레이 중 장식 헤더를 접고 상태·게임판을 한 viewport 안에 유지한다. 두 이미지는 1~3배 확대와 드래그 이동을 동기화하며, 드래그는 정답 선택으로 처리하지 않는다. 어떤 확대·배치에서도 변경본 좌표를 정규화해 같은 정답으로 판정한다.

## 결과·취소 화면

- 승리·패배·무승부 또는 취소
- 양쪽 완료 문제 수, 총 발견 수와 오답 수
- 양쪽 정답 점수, 완주 시간 가산점과 총점
- 종료·취소 사유와 경기 시간
- 로비로 돌아가기
- 문제 신고 사유와 신고 완료 상태

문제별 전체 정답 검토, 재대전과 즉시 새 매칭은 후속 기능이다.

## 접근성·오류

- 모든 조작에 키보드 포커스와 접근 가능한 이름
- 입력 잠금과 카운트다운을 시각 외 방식으로도 안내
- 확대 배율, 축소·확대·원래 크기와 드래그 안내
- 이미지 로드 실패 재시도 또는 경기 취소
- 재접속 유예의 실제 남은 시간과 상태 복구
- 연결·서버 오류별 사용자가 취할 행동
- 동작 감소, 색각·고대비와 스크린리더 검수

지원 기기·브라우저와 접근성 목표는 `REVIEW_REQUIRED.md`의 `REV-011`에서 확정한다.
