# MVP 결정 기록

## 목적

구현을 시작하기 전에 범위와 정책을 고정한다. 변경이 필요하면 기존 문서를 조용히 덮어쓰지 않고 이 문서에 근거와 영향을 기록한다.

## 확정 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 사용자 | 계정 없는 게스트 세션과 닉네임 | 가입 장벽 없이 핵심 게임을 검증하기 위해 |
| 대전 | 무작위 1대1 빠른 대전만 제공 | 매칭과 핵심 루프에 집중하기 위해 |
| 차이점 수 | 플레이어당 3개 | 30초 제작과 60초 풀이에 적합한 초기 기준 |
| 원본 이미지 | 사전 검증한 10장 | 콘텐츠 품질을 통제하면서 반복 테스트하기 위해 |
| 제작 도구 | 추가, 가리기, 색상 변경 | 서로 다른 제작 방식을 최소 범위로 검증하기 위해 |
| 제작 미완료 | 마감 직전 제작자 클라이언트가 부족한 차이를 자동 보충 | 경기 중단과 의도적인 시간 끌기를 막기 위해 |
| 문제 교환 방식 | 제작자가 렌더한 이미지 한 장만 상대에게 전달 | 제작 명령을 넘기면 정답 위치가 그대로 노출되기 때문 |
| 시간 판정 | 서버 마감 시각 기준 | 네트워크와 기기 시간 차이에 의한 불공정을 막기 위해 |
| 재접속 | 10초 유예 후 기권 | 짧은 연결 장애를 흡수하면서 경기를 무한 대기시키지 않기 위해 |
| 플랫폼 | 데스크톱과 모바일 웹 | 포인터와 터치 좌표 정확도를 초기에 함께 검증하기 위해 |
| 신고 | 저장 및 운영자 확인, 자동 제재 없음 | 오판 위험 없이 사례를 먼저 수집하기 위해 |
| 이미지 업로드 | 제공하지 않음 | 저작권, 유해 콘텐츠, 저장 비용 문제를 MVP에서 제외하기 위해 |
| 수익화 | 재화, 상점, 유료 기능 없음 | 핵심 재미와 공정성 검증에 집중하기 위해 |

## MVP 성공 조건

- 두 브라우저가 매칭부터 결과까지 실제 서버를 통해 한 판을 완주한다.
- 양쪽의 상태, 남은 시간, 정답 수, 승패가 일치한다.
- 데스크톱과 모바일에서 정규화 좌표 판정이 동일하다.
- 제작 미완료, 직접 이탈, 일시적 연결 끊김, 서버 오류가 정의된 결과로 끝난다.
- 소규모 플레이테스트에서 경기 완주율과 재플레이 의향을 측정할 수 있다.

## 보류 기능

- 회원 계정과 프로필 성장
- 랭킹, 시즌, 퀘스트, 업적
- 재화, 상점, 결제
- 친구, 초대 링크, 채팅
- 데일리 도전
- 사용자 이미지 업로드
- 관전, 리플레이, 다인전

보류 기능은 핵심 경기의 완주율과 재플레이 의향이 확인된 뒤 우선순위를 다시 정한다.

### 2026-07-20 — 문제 교환 방식 변경

**무엇을 바꿨나**

풀이 클라이언트에 상대의 `Difference[]`를 전달하던 것을, 제작자가 합성한 이미지 한 장만
전달하도록 바꿨다. 정답 좌표(`region`)와 제작 명령(`strokes`, `fill`)은 서버 밖으로 나가지 않는다.

**왜**

기존 `GameMatch.snapshot(viewerId)`는 `FINDING` 상태에서 상대의 차이점 배열을 그대로 내보냈다.
풀이 클라이언트가 그림을 합성하려면 제작 명령이 필요한데, **제작 명령 자체가 정답 위치**다.
개발자도구에서 소켓 메시지만 열어봐도 세 곳이 전부 보이는 상태였다.
`TEST_PLAN.md` 6절의 "정답 좌표 또는 상대 제작 데이터의 조기 노출 여부"에 정면으로 걸린다.

서버가 대신 렌더하는 방법도 있지만 서버에 이미지 처리 의존성이 붙는다.
제작자는 어차피 자기 정답을 알고 있으므로, 제작자 쪽에서 합성을 끝내고 결과만 올리면
서버는 픽셀을 만지지 않고도 정답을 독점할 수 있다.

**영향**

- `GameSnapshot.problem` 삭제 → `problemImage`, `foundMarks`, `revealedDifferences`로 분리
- `game:submit` 이벤트에 `renderedImage` 추가. 서버는 형식과 용량만 검증한다
- 클릭 판정은 기존대로 서버가 수행. 맞힌 차이점의 위치만 응답에 포함한다
- 전체 정답은 `FINISHED` 이후에만 공개한다
- 영향 문서: `TECH_SPEC.md`(4·6·10절), `GAME_STATE.md`(6절), `TEST_PLAN.md`(6절)

### 2026-07-20 — 자동 보충 주체 이동

**무엇을 바꿨나**

서버가 준비된 후보로 부족한 차이점을 채우던 설계를, 제작자 클라이언트가 마감
`autoSubmitLeadSeconds`(3초) 전에 스스로 채워 제출하는 방식으로 바꿨다.

**왜**

위 변경으로 문제 이미지를 만들 수 있는 주체가 제작자 클라이언트뿐이 되었다.
서버가 차이점을 주입해도 그에 맞는 이미지를 렌더할 수 없어 교환할 문제가 생기지 않는다.

실제로 기존 코드의 서버측 `FALLBACK_DIFFERENCES`는 생성자에서 검증만 되고
**어디에서도 사용되지 않았다.** 자동 보충은 구현된 적이 없었고 자리만 잡혀 있었다.

**영향**

- `GameMatch` 생성자에서 `fallbackDifferences` 인자 제거
- `MatchRegistry`의 `FALLBACK_DIFFERENCES` 삭제
- `PlayerProgress.autoFilled` 추가 — 화면에 자동 보충 사실을 안내하기 위해
- 클라이언트 자동 제출이 실패하면 서버는 미제출로 보고 기권 처리한다
- 남은 위험: 연결이 끊긴 채 마감을 맞으면 자동 보충이 동작하지 않는다.
  이 경우는 재접속 유예(10초)와 기권 규칙이 처리한다
