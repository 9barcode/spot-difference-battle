| 수익화 | MVP 제외 | 핵심 재미와 공정성에 집중 |

## 2. 성공 조건

- 제작자와 찾는 사람이 실제 서버로 한 판을 완주한다.
- 양쪽의 역할, 상태, 마감 시각, 진행도와 승패가 일치한다.
- 찾는 사람에게 미발견 정답과 제작 데이터가 노출되지 않는다.
- 데스크톱과 모바일에서 같은 정규화 좌표가 같은 답으로 처리된다.
- 자동 보충, 직접 이탈, 재접속 실패와 서버 오류가 정의된 결과로 끝난다.
- 출시 후보 장면의 라이선스와 운영 감사 데이터가 준비된다.

## 5. 주요 결정 근거

### 렌더 이미지 전달

제작 명령과 정답 좌표를 찾는 사람에게 보내면 개발자 도구에서 정답을 확인할 수 있다. 제작자가 합성한 결과 이미지만 전달하고 서버가 정답 판정을 독점한다.

### 비대칭 역할

양쪽이 동시에 문제를 제작하고 푸는 구조는 대기·교환·동점 판정이 복잡하고 제작 중 정보 분리가 어렵다. 제작자와 찾는 사람을 분리해 한 번의 제출과 한 번의 풀이로 세로형 MVP를 단순화했다.

### 객체 편집

픽셀 색상 유사도 방식은 작은 화면과 복잡한 장면에서 선택 범위가 불안정했다. 장면별 수동 객체 마스크를 사용해 클릭 영역과 정답 영역을 고정한다.

### 자동 보충

서버는 문제 이미지를 렌더하지 않으므로 부족한 차이를 서버가 추가하면 그에 맞는 이미지가 없다. 제작자 클라이언트가 마감 직전에 장면별 후보를 사용해 합성과 제출을 함께 수행한다.

연결이 끊긴 상태에서 자동 제출하지 못하면 서버는 최종 미제출로 보고 제작자 기권을 확정한다.
