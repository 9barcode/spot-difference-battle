# 2026-08-31 변경 요약 — 개발·운영 문서 체계 확립

> 문서 상태: HISTORICAL

## 감사 범위

- 제품·규칙·상태·화면·기술·테스트·에셋·배포 문서 전체
- 공유 설정, 게임 코어, 서버 저장·복구, UI와 자동 테스트
- Git 저장소 구조와 현재 스테이징 준비 상태

## 확인한 문제

- 문서는 많지만 작업 시작점, 권한 순위와 완료 기준이 분산돼 있었다.
- 게임 동점 규칙, 활성 문제 수, 취소 상태와 구형 코드 설명이 CURRENT 문서 사이에서 충돌했다.
- 기능 구현 완료와 공개 출시 준비 완료가 구분되지 않았다.
- AI 작업 범위·검증·인수인계 기준, CI·운영·장애·백업·유지보수 기준이 없었다.
- 실제 경기 판정과 다른 구형 승패 함수, 불완전한 장면 식별자 타입과 중첩 저장소 구조가 남아 있었다.

## 정리한 체계

- `docs/README.md`를 단일 문서 포털로 추가
- 프로젝트 헌장과 8단계 개발 생명주기 추가
- AI 협업 규칙, 루트 `AGENTS.md`와 기여 가이드 추가
- 품질 게이트, 요구사항 추적표와 운영·유지보수 기준 추가
- 변경 계약, 결정, 인수인계, 출시, 장애와 문제 QA 템플릿 추가
- 사람 승인과 외부 검증이 필요한 항목을 `REVIEW_REQUIRED.md`로 분리
- 기존 CURRENT 문서를 코드와 확정 규칙에 맞게 교정

## 검증 기준

문서 감사의 코드 기준점은 2026-08-30 실행한 `pnpm check`, `pnpm test`, `pnpm build` 통과 결과다. 단위·통합 63개가 통과했고 실제 PostgreSQL 2개는 건너뛰었다. 이번 변경은 문서만 수정하며 게임 코드는 변경하지 않았다.

문서 링크, 상태, 수치와 금지된 구형 표현은 별도 검색으로 다시 검증한다.
