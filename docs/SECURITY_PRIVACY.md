# 보안과 개인정보 설계

> 문서 상태: CURRENT
> 기준일: 2026-09-04
> 책임 역할: 기술·보안·개인정보 책임자

## 범위와 목표

게스트 기반 실시간 1대1 게임의 클라이언트, Socket.IO 서버, HTTP 엔드포인트, PostgreSQL, 배포 환경과 공급망을 다룬다. 목표는 정답·경기 상태 조작, 세션 탈취, 입력 남용, 개인정보 과수집, 비밀 노출과 취약한 배포를 예방하고 사고를 재현할 증거를 남기는 것이다.

## 신뢰 경계와 자산

| 경계 | 신뢰하지 않는 입력 | 보호 자산 | 핵심 통제 |
|---|---|---|---|
| WebView/브라우저 → 서버 | 모든 이벤트 payload, 좌표, 상태·버전, 닉네임 | 경기 무결성, 세션 | 런타임 검증, 소유권·상태 검사, 속도 제한 |
| 서버 → 클라이언트 | 공개 가능한 스냅샷만 허용 | 미발견 정답, 상대 좌표 | 역할별 직렬화, 서버 전용 정답 데이터 |
| 서버 → PostgreSQL | 애플리케이션 데이터 | 활성·완료 경기, 신고 | 매개변수화 쿼리, 최소 권한, 마이그레이션 |
| CI·배포 → 운영 | 코드·의존성·환경 설정 | 비밀정보, 릴리스 무결성 | 잠금 파일, 검증 게이트, 비밀 분리, 승인 커밋 |
| 앱인토스 호스트 → 미니앱 | origin, Safe Area, 생명주기 | 사용자 경험, 네트워크 정책 | 허용 origin, HTTPS/WSS, SDK 계약 검증 |

## 최소 보안 요구사항

- 서버는 시간·정답·점수·승패를 최종 판정한다.
- 모든 외부 payload는 타입·길이·범위·상태·소유권을 런타임에서 검증한다.
- 미발견 정답 전체와 상대의 정확한 발견 좌표를 경기 중 클라이언트에 보내지 않는다.
- 게스트 토큰, DB URL과 운영 비밀은 저장소·로그·클라이언트 번들에 포함하지 않는다.
- 운영은 HTTPS/WSS만 사용하고 CORS는 정확한 origin 허용 목록을 사용한다.
- 오류 응답과 로그에는 토큰·정답 전체·불필요한 개인정보를 기록하지 않는다.
- 의존성은 잠금 파일로 재현하고 릴리스마다 프로덕션 취약점을 검사한다.
- 취약점은 심각도, 영향, 우회책, 담당자와 해결 기한으로 추적한다.

## 개인정보

현재 식별 정보는 게스트 닉네임과 임시 세션 식별자이며, 경기·신고 데이터가 저장될 수 있다. 공개 출시 전 다음을 제품·개인정보 책임자가 승인해야 한다.

- 항목별 수집 목적과 법적 근거
- 저장 위치, 접근 역할과 제3자 처리자
- 목적별 보존 기간과 자동 삭제·익명화 절차
- 사용자 고지, 열람·삭제 요청 처리와 연락처
- 로그·백업에 남는 데이터의 보존과 파기
- 아동 또는 연령 제한이 필요한 경우의 처리

승인된 보존표와 고지문이 없으므로 개인정보 운영 준비 상태는 `NOT_READY`다.

## 검증 게이트

- 기본: 타입 검사, 단위·통합 테스트, 프로덕션 빌드
- 입력·세션: 변조 payload, 다른 경기·사용자 접근, 재전송, 속도 제한
- 정보 공개: 번들·네트워크 스냅샷·로그에서 정답·토큰 노출 확인
