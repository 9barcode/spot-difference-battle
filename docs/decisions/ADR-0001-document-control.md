# ADR-0001 — 증거 기반 경량 문서 통제

> 상태: ACCEPTED
> 결정일: 2026-09-04
> 결정권자: 프로젝트 소유자 요청에 따른 문서 체계 결정

## 맥락

문서 수가 늘면서 테스트 개수·완료 상태가 중복되고, 템플릿은 있지만 실제 변경 계약과 승인 체크리스트가 사용되지 않았다. 대규모 표준 문서를 그대로 도입하면 유지 비용이 커지고, 현재 방식만 유지하면 출시 증거가 분산된다.

## 결정

- 요구사항·아키텍처·보안·접근성·운영 표준은 `STANDARDS_PROFILE.md`에서 프로젝트 규모에 맞게 조정한다.
- 제품·규칙·기술 등 질문별 정본은 유지하되 검증 실행 결과는 `VERIFICATION_EVIDENCE.md` 한 곳에서 관리한다.
- 보안·개인정보는 `SECURITY_PRIVACY.md`를 정본으로 둔다.
- 고위험 변경은 작성된 변경 계약과 ADR, 출시 후보는 인스턴스화된 체크리스트를 사용한다.
- 외부 검수는 증거가 없으면 `NOT_READY`이며 자동 테스트로 대체하지 않는다.

## 결과

중복 숫자와 거짓 완료를 줄이고, 현재 상태·승인·증거를 분리할 수 있다. 대신 변경마다 문서 상태와 증거 링크를 유지해야 한다.

## 대안

- 기존 날짜별 변경 기록만 사용: 사전 결정과 승인 증거가 부족해 기각.
- ISO 문서 구조 전체 도입: 현재 팀 규모에 과도해 기각.
- 단일 거대 설계서: 소유권과 변경 충돌이 커져 기각.
