# 게임 상태

> 문서 상태: CURRENT
>
> 기준일: 2026-07-29
> 서버의 실제 상태 전이와 허용 입력을 설명한다.

## 1. 경기 상태

| 상태 | 의미 | 종료 조건 |
|---|---|---|
| `LOBBY` | 클라이언트 로비 | 매칭 시작 |
| `MATCHING` | 빠른 대전 대기 | 상대 매칭 또는 사용자가 취소 |
| `READY` | 역할 확인과 양쪽 준비 | 두 플레이어 준비 완료 |
| `EDITING` | 제작자가 차이점 제작, 찾는 사람 대기 | 제작자 제출 또는 제작 시간 종료 |
| `SWAPPING` | 제출 승인 후 문제 전달을 위한 내부 전이 | 즉시 `FINDING` |
| `FINDING` | 찾는 사람이 문제 풀이, 제작자는 진행도 관전 | 3개 발견, 시간 종료, 기권 또는 오류 |
| `FINISHED` | 승패와 결과 확정 | 클라이언트가 로비로 이동 |
| `CANCELLED` | 신뢰할 수 없는 서버 오류로 경기 취소 | 클라이언트가 로비로 이동 |

## 2. 정상 전이

`LOBBY → MATCHING → READY → EDITING → SWAPPING → FINDING → FINISHED`

`SWAPPING`은 제작자 제출 처리 중 연속 전이하므로 화면에서 관찰되지 않을 수 있다. 재대전 전이는 현재 없다. 새 경기는 로비에서 다시 매칭해 별도 경기 ID로 시작한다.

## 3. 역할별 입력

| 상태 | 제작자 | 찾는 사람 |
|---|---|---|
| `READY` | 준비 완료, 나가기 | 준비 완료, 나가기 |
| `EDITING` | 로컬 편집, 제출, 나가기 | 나가기 |
| `SWAPPING` | 입력 없음 | 입력 없음 |
| `FINDING` | 나가기 | 위치 선택, 힌트, 나가기 |
| `FINISHED` | 로비, 신고 | 로비, 신고 |
| `CANCELLED` | 로비, 신고 | 로비, 신고 |

객체 추가·수정·삭제는 제작자 클라이언트의 로컬 편집이다. 서버에 전달되는 제작 입력은 최종 제출뿐이다.

## 4. 시간 종료

- `EDITING`: 유효한 제출이 없으면 제작자가 기권하고 찾는 사람이 승리한다.
- `FINDING`: 찾는 사람이 3개를 완료하지 못하면 제작자가 승리한다.
- 서버 마감 시각이 최종 기준이며 클라이언트 카운트다운은 표시용이다.

## 5. 연결 상태

연결 상태는 경기 상태와 별도로 플레이어별로 관리한다.

- `CONNECTED`: 정상 연결
- `RECONNECTING`: 연결 상실 후 복귀 유예 중
- `FORFEITED`: 직접 이탈 또는 유예시간 초과

별도의 `DISCONNECTED` 값은 사용하지 않는다. 연결 상실을 감지하면 곧바로 `RECONNECTING`으로 표시한다. 경기 타이머는 계속 흐르며 10초 안에 복귀하지 않으면 상대의 기권승으로 끝난다.

## 6. 취소와 미완료 예외

서버는 경기 판정을 신뢰할 수 없는 처리·저장 오류에서 `CANCELLED`로 전환할 수 있다. 현재 다음 항목은 문서에 목표 동작만 두지 않고 백로그에서 미완료로 관리한다.

- 매칭 대기 시간초과
- 이미지 로드 완료 서버 승인과 실패 취소
- 장면별 서버 원본 검증 실패 처리

## 7. 상태 동기화

- 서버 스냅샷의 `stateVersion`이 경기 상태의 순서를 결정한다.
- 클라이언트는 같은 경기의 현재 버전 이하 스냅샷을 무시한다.
- 추측·힌트·기권·신고는 현재 상태와 정확히 같은 버전만 허용한다.
- 제작 제출은 현재 상태가 `EDITING`인 동안 현재 버전보다 미래인 값만 거절하며, 연결 상태 변경 등으로 버전이 오른 경우의 이전 버전 제출은 코어의 제출·마감 검사를 다시 거쳐 허용할 수 있다.
- 스냅샷은 서버 마감 시각 `deadlineMs`를 포함한다.
- 일반 `serverTime`과 이벤트별 `eventId`는 현재 포함하지 않으며 기술 백로그로 관리한다.
