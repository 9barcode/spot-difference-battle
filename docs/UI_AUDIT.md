# UI 현황 점검

> 문서 상태: CURRENT
> 기준일: 2026-07-30
> 현재 UI를 점검하는 파생 문서이며 게임 규칙은 `GAME_RULES.md` 하나를 따른다.

## 1. 기준 화면

- 활성 앱: `UI/src/main.tsx`가 렌더하는 `UI/src/app/MvpApp.tsx`
- 비활성 참고 시안: `UI/src/app/App.tsx`
- 유일한 게임 규칙 정본: `GAME_RULES.md`
- 현재 화면 요구: `SCREEN_SPEC.md`

`App.tsx`는 Figma Make에서 가져온 과거 시안이다. 차이점 5개, 로그인 프로필, 재화, 랭킹, 상점, 시즌과 퀘스트가 포함돼 있으며 현재 앱에서 렌더하지 않는다. 구현 기준이나 완료 기능으로 취급하지 않는다.

## 2. 현재 구현된 핵심 화면

- 닉네임 입력과 로비
- 빠른 대전 매칭 대기와 취소
- 역할 확인과 준비
- 제작자 객체 편집
- 찾는 사람 비공개 대기
- 찾는 사람 풀이와 제작자 진행도 관전
- 재접속·상대 복귀 대기 안내
- 승패·기권·취소 결과
- 전체 정답 공개
- 신고 사유와 접수 완료
- 1인 제작·풀이 테스트
- 모바일 반응형 배치와 정규화 좌표

## 3. 현재 화면과 명세의 보완점

### 높은 우선순위

- 재접속 유예시간 실제 카운트다운과 수동 재시도
- 매칭 경과 시간과 시간초과
- 이미지 로드 준비 실패 화면
- 결과 완료 시간과 단계별 소요 시간
- 신고 문제를 운영자가 재확인할 수 있는 데이터 연결
- 모든 화면의 키보드·스크린리더·색각 접근성

### 보통 우선순위

- 브라우저 `prompt` 대신 접근 가능한 신고 대화상자
- 제작 자동 보충과 이미지 생성 재시도 설명 개선
- 서버 오류 코드별 사용자 행동 안내
- 청각 피드백 또는 동등한 추가 감각 피드백

### 보류 기능

- 재대전 요청·수락·거절·시간초과
- 결과 화면의 즉시 새 매칭
- 랭킹·상점·시즌·퀘스트·친구 대전

## 4. 정리 원칙

- 활성 UI와 비활성 시안의 문서·파일 설명을 구분한다.
- 비활성 시안을 유지한다면 파일 상단 또는 별도 `legacy` 디렉터리로 상태를 표시한다.
- 실제 제공하지 않는 기능은 화면 명세의 현재 요구가 아니라 백로그에 둔다.
- 차이점 수와 시간은 UI에 직접 중복 기재하지 않고 공유 `GAME_CONFIG`를 사용한다.
