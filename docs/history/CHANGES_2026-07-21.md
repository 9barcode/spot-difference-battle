# 변경 요약 — pnpm dev 자동 사전 빌드 (2026-07-21)

> 문서 상태: HISTORICAL
> 현재 실행 방법은 루트 `README.md`를 따른다. 이 문서의 변경 배경은 당시 기록으로 보존한다.

## 한 줄 요약

`pnpm dev`만 쳐도 내부 패키지가 자동으로 먼저 빌드되도록 최상위 `package.json`에 `predev`를 추가했다.

## 왜 필요했나

서버(`apps/server`)는 내부 패키지 `@spot-battle/game-core`의 빌드 결과물(`dist/`)을
import한다. 그런데 기존 `pnpm dev`는 웹과 서버만 띄우고 `packages/shared`·
`packages/game-core`는 빌드하지 않았다.

그 결과 리포를 새로 받아 `pnpm dev`를 처음 실행하면 `dist/`가 없어서 서버가
`ERR_MODULE_NOT_FOUND`로 조용히 죽었다. 서버가 없으니 웹은 "서버 연결 중"에서 멈췄다.
증상은 "매칭이 안 됨"으로 보이지만 실제 원인은 서버 미기동이었다.

## 무엇을 바꿨나

최상위 `package.json`의 `scripts`에 세 가지를 정리했다.

- `build:packages` — shared·game-core만 빌드하는 스크립트
- `predev` — pnpm이 `dev` 직전에 자동 실행하는 훅. `build:packages`를 호출한다
- `setup` — 리포를 처음 받았을 때 `install` + 패키지 빌드를 한 번에

이제 `pnpm dev` 하나로 패키지 빌드 → 웹·서버 기동이 순서대로 이뤄진다.

## 검증

`packages/*/dist`를 지운 상태에서 `pnpm dev`만 실행:

- `predev`가 자동으로 shared·game-core를 빌드함
- 웹 기동: http://localhost:5173/ → HTTP 200
- 서버 기동: http://localhost:3001/health → {"status":"ok","server":"ok","database":true}

## 처음 받은 사람용 안내

```
pnpm setup    # 한 번만: 설치 + 패키지 빌드
pnpm dev      # 이후로는 이것만. 웹 5173 / 서버 3001
```

두 명이 필요한 게임이므로, 로컬에서 혼자 테스트할 때는 일반 창 + 시크릿 창처럼
세션이 분리된 창 두 개로 각각 "빠른 대전"을 눌러야 매칭된다.
