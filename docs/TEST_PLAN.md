# 테스트 계획

> 문서 상태: CURRENT
>
> 기준일: 2026-07-29
> 현재 자동화 범위와 출시 전 필요한 검증을 구분한다.

## 1. 출시 전 필수 조건

- 제작자와 찾는 사람이 정상 경기를 완주하고 같은 결과를 받는다.
- 제작 중 찾는 사람에게 이미지·객체·미발견 정답이 노출되지 않는다.
- 차이점 3개, 서버 마감 시각, 오답 3초 차감과 힌트 1회가 일치한다.
- 제작·찾기 시간초과와 기권이 역할별 규칙대로 끝난다.
- 데스크톱·모바일의 정규화 좌표가 일치한다.
- 연결 및 서버 오류가 정의된 방식으로 복구되거나 종료된다.
- 출시 장면의 라이선스와 서버 원본 검증이 완료된다.
- 조작된 객체 ID·중복 객체·허용되지 않은 효과를 서버가 거절한다.
- 신고된 문제를 운영자가 재검토할 수 있는 데이터가 보존된다.

## 2. 현재 자동화된 범위

### 게임 코어

- 차이점 3개의 경계·중복·최소 간격 검증
- 제작자만 제출 가능
- 찾는 사람만 추측·힌트 가능
- 제작 미제출 시 찾는 사람 기권승
- 정답·오답 3초 차감·중복 정답 무페널티
- 힌트 1회
- 찾는 사람 완료 승리와 찾기 시간초과 제작자 승리
- 역할별 직접 기권
- 풀이 중 정답 비공개와 종료 후 전체 공개
- 활성 경기 직렬화·복구

구형 점수 비교 `determineWinner` 단위 테스트가 남아 있지만 현재 비대칭 `GameMatch` 승패 경로에서는 사용하지 않는다. 제거 또는 별도 실험 규칙으로 격리해야 한다.

### 서버

- 실제 PNG 문제 이미지와 정답 좌표의 픽셀 변화 검증
- 모든 공유 장면 ID의 서버 원본 등록
- 장면 객체 ID·중복 객체·허용 효과 검증
- 제작자 제출부터 찾는 사람 정상 완료까지 통합 흐름
- 오래된 상태와 연속 입력 차단
- 게스트 토큰 재접속
- 재접속 유예시간 초과 기권
- 활성 상태와 완료 경기·신고 저장
- 저장 실패 후 서버 판정 유지
- PostgreSQL 서버 재시작 복구 테스트는 `DATABASE_URL`이 있을 때만 실행

### 웹과 브라우저

- 지연·중복 스냅샷 무시
- 장면 카탈로그 등록·후보 검증·기본 장면 대체
- 키보드로 닉네임 저장과 매칭 시작
- 독립 브라우저 두 개의 매칭·역할·준비
- 제작 중 찾는 사람 화면 비공개
- 데스크톱 제작자와 모바일 찾는 사람 조합
- 객체 3개 선택과 풀이 화면 진입
- 기권 결과의 양쪽 동기화
- Chromium·Firefox·WebKit 실행

## 3. 자동화가 부족하거나 없는 범위

- 브라우저에서 정답 3개를 직접 찾아 정상 결과까지 완주
- 브라우저 제작·찾기 실제 시간초과
- 마감 3초 전 자동 보충과 합성 실패 재시도
- 브라우저 새로고침과 재접속, 여러 탭 충돌
- 실제 네트워크 제한·패킷 손실·오프라인 전환
- PostgreSQL 복구의 상시 CI 실행
- 매칭 대기 시간초과와 이미지 로드 준비 실패
- 실제 두 번째 장면의 원본·마스크·효과 경계 통합 검증
- 결과 문제 이미지·정답의 운영 감사
- 모든 화면의 키보드 탐색과 스크린리더 이름
- 색각 이상, 축소·확대, 저사양 모바일
- 재대전과 결과 화면 새 매칭
- 청각 피드백 대체 수단

## 4. 기능 테스트

### 매칭·준비

- 첫 참가자가 제작자, 두 번째가 찾는 사람인지 확인한다.
- 매칭 취소가 기권으로 기록되지 않는지 확인한다.
- 양쪽 준비 후에만 제작이 시작되는지 확인한다.
- 같은 `imageId`가 양쪽과 복구 후에도 유지되는지 확인한다.

### 제작

- 장면의 모든 객체를 모바일에서도 독립 선택할 수 있는지 확인한다.
- 객체 효과가 객체 경계를 벗어나지 않는지 육안 확인한다.
- 저장·수정·삭제 후 정확히 3개만 제출되는지 확인한다.
- 이미지와 정답 좌표가 다르면 서버가 거절하는지 확인한다.
- 찾는 사람 네트워크 payload에 제작 정보가 없는지 확인한다.
- 자동 보충 성공·실패와 제작자 기권을 확인한다.

### 풀이

- 정답은 한 번만 인정되는지 확인한다.
- 이미 찾은 영역 재선택에 페널티가 없는지 확인한다.
- 오답마다 실제 마감이 3초 줄어드는지 확인한다.
- 힌트가 미발견 정답을 대상으로 한 번만 동작하는지 확인한다.
- 제작자는 추측할 수 없는지 확인한다.
- 마감 이후 입력이 결과를 바꾸지 않는지 확인한다.

### 결과

- 3개 완료는 찾는 사람 승리인지 확인한다.
- 찾기 시간초과는 제작자 승리인지 확인한다.
- 제작 미제출·직접 이탈·재접속 실패의 상대 승리를 확인한다.
- 취소 경기는 승패에 포함되지 않는지 확인한다.
- 전체 정답은 결과에서 처음 공개되는지 확인한다.
- 로비 이동과 한 경기당 한 번 신고가 동작하는지 확인한다.

## 5. 접근성·보안·운영

- 색상만으로 정답·오답을 구분하지 않는다.
- 포커스 표시와 키보드 입력 차단 상태를 확인한다.
- 닉네임과 신고 설명의 길이·문자 검증을 확인한다.
- 다른 경기·다른 역할의 요청을 거절하는지 확인한다.
- 과도한 추측·힌트 요청을 제한하는지 확인한다.
- 로그와 저장 데이터에 불필요한 인증 정보가 없는지 확인한다.
- 라이선스 미확인 장면이 출시 환경에 포함되지 않는지 확인한다.

## 6. 결함 우선순위

- 치명적: 진행 불가, 잘못된 승패, 정답 노출, 데이터 손실
- 높음: 핵심 역할·타이머·복구 불일치, 신고 감사 불가
- 보통: 우회 가능한 화면·접근성·운영 문제
- 낮음: 결과에 영향 없는 표현과 시각 문제

치명적·높음 결함은 출시 전에 동일 조건으로 재검증한다.
