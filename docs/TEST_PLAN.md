# 테스트 계획

> 문서 상태: CURRENT
> 기준일: 2026-08-31
> 책임 역할: QA 책임자
> 기대 동작은 `GAME_RULES.md`, 변경별 필수 범위는 `QUALITY_GATES.md`를 따른다.

## 1. 출시 전 핵심 조건

- 두 플레이어가 동일한 문제 순서와 버전을 받는다.
- 이미지 로드 완료 후 같은 서버 시각에 시작한다.
- 각 플레이어가 독립적으로 문제를 완료하고 다음 문제로 이동한다.
- 문제별 실제 차이 수, 난이도별 오답 잠금과 서버 마감이 일치한다.
- 첫 완주, 정답 점수, 완주 시간 가산점, 제한시간 오답 우선순위와 무승부가 정확하다.
- 상대의 정답 위치와 이후 문제 정답이 종료 전에 노출되지 않는다.
- 데스크톱·모바일의 확대·정규화 좌표가 일치한다.
- 재접속, 이탈, 로드 실패와 서버 오류가 정의된 결과로 끝난다.
- 모든 문제 쌍의 이미지·정답·버전·권리 상태를 재검토할 수 있다.

## 2. 코어 단위 테스트

- `READY → PRELOADING → COUNTDOWN → PLAYING → FINISHED/CANCELLED` 전이
- 플레이어별 독립 문제 인덱스와 발견 집합
- 정답, 오답, 중복 정답 무페널티와 난이도별 입력 잠금
- 현재 문제의 실제 차이를 모두 찾은 뒤 다음 문제 이동
- 정답 점수·완주 시간 가산점, 제한시간 오답 우선순위와 무승부
- 첫 전체 덱 완주 시 제한시간 전 즉시 종료하고 양쪽에 같은 승패 표시
- 생존전 3회 오답 즉시 패배
- 마감 이후·잠금 중·잘못된 문제 입력 차단
- 직접 이탈·재접속 실패 기권과 신뢰 불가 취소
- 직렬화·복구 후 동일한 문제 순서와 진행 유지

승패 테스트는 실제 서버 권위 `GameMatch`의 첫 완주·시간 종료·오답·무승부 경로만 검증한다. 별도 공개 판정 함수는 두지 않는다.

## 3. 서버 통합 테스트

- 같은 설정 매칭과 같은 문제 순서 배정
- 문제 ID·에셋 버전 로드 승인과 공통 시작 시각
- 현재 문제의 서버 정답 영역 판정
- 조작된 payload, `pairId`, 문제 인덱스, 버전과 좌표 차단
- 상대에게 정답 위치가 없는 스냅샷
- 한쪽의 다음 문제 이동이 상대 진행을 바꾸지 않음
- 동시 입력과 시간 종료의 결정적 결과
- 첫 완주 결과 저장 실패 시 잘못된 신고·정리 차단
- 완료 경기의 문제 매니페스트·양쪽 결과 저장과 중복 신고 차단
- 손상 활성 경기 격리와 정상 경기 복구 지속
- PostgreSQL 재시작 후 진행 복구와 감사 데이터 저장

마지막 PostgreSQL 항목은 실제 테스트 DB가 있을 때만 실행된다. 건너뛴 결과는 검증 완료가 아니다.

## 4. 웹 단위 테스트

- 서버 URL과 로컬 LAN 주소 계산
- 이미지 표시 영역과 정규화 좌표
- 오래되거나 중복된 서버 스냅샷 무시
- 웹 자산과 공유 매니페스트 파일·버전·해시 일치
- 난이도별 문제 자산 선택

## 5. 브라우저 E2E

- 두 브라우저 매칭·준비·사전 로드·카운트다운
- 같은 원본·변경본과 선택 난이도 풀 표시
- 한 플레이어만 먼저 다음 문제로 이동
- 상대 진행 수치만 표시하고 정답 위치 숨김
- 첫 전체 덱 완주 즉시 종료와 상대 패배 결과 동기화
- 제한시간 결과와 점수 구성 동기화
- EASY·NORMAL(MEDIUM)·HARD에 등급 문제와 UNRATED만 배정
- 데스크톱·모바일 확대·드래그·정규화 좌표
- 새로고침·재접속과 다중 탭
- 키보드 포커스와 기본 접근 가능한 이름
- Chromium·Firefox·WebKit

자동 설정은 390×844 세로 모바일, 844×390 및 640×360 가로 게임 WebView와 1280×900 데스크톱 조합을 사용한다. 가로 게임 WebView에서는 두 게임판이 첫 viewport 안에서 좌우로 보이는지도 검증한다. 실기 검수에서는 실제 PC와 휴대폰으로 선택한 난이도 전체 덱, Safe Area, 확대·드래그, 오답 잠금, 다음 문제와 결과를 확인한다.

## 6. 문제 에셋 검수

- 원본·변경본 크기, 비율, 크롭과 버전 일치
- 의도한 정답 영역과 매니페스트의 실제 수 일치
- 영역 밖 생성형 미세 변화가 정답으로 등록되지 않음
- 모바일에서 각 차이를 독립적으로 식별 가능
- 텍스트·상표·워터마크·부적절한 표현 없음
- 출처, 생성 도구, 이용 조건과 권리 승인
- 문제별 풀이 시간·오답률·신고율 검토

현재 활성 16쌍은 자동 픽셀 비교가 아니라 수동 정답 영역을 사용한다. 자동 파일·좌표 검증과 별개로 모든 활성 버전에 `templates/PUZZLE_QA.md` 기반 육안·권리 승인이 필요하다.

## 7. 접근성·보안·운영

- 색상만으로 정답·오답·잠금을 구분하지 않는다.
- 키보드 포커스와 스크린리더 이름을 확인한다.
- 확대·드래그가 정답 클릭으로 오인되지 않는다.
- 과도한 선택 요청과 다른 경기 입력을 제한한다.
- 로그에 토큰, 정답 전체와 불필요한 개인정보가 노출되지 않는다.
- 신고된 문제를 정확한 버전으로 재현할 수 있다.
- Docker 이미지, `/health`, DB 마이그레이션과 롤백을 스테이징에서 검증한다.

## 8. 최근 검증 기준

2026-08-30 로컬에서 다음이 통과했다.

- `pnpm check`
- `pnpm test`: 단위·통합 63개 통과, 실제 PostgreSQL 2개 건너뜀
- `pnpm build`

이번 기록은 다음 코드·에셋·설정 변경 전까지만 기준점으로 사용한다. 브라우저 E2E, 실제 PostgreSQL, 스테이징·실기기 검수는 다음 릴리스 전에 별도 실행해야 한다.

## 9. 결함 우선순위

- 치명적: 광범위한 진행 불가, 잘못된 승패, 정답 노출, 데이터 손실, 양쪽 문제 순서 불일치
- 높음: 타이머·점수·복구·매칭·이미지 로드 공정성 오류
- 보통: 우회 가능한 화면·접근성·운영 문제
- 낮음: 결과에 영향 없는 표현과 시각 문제
