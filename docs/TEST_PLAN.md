# 테스트 계획

## 1. 목적

핵심 게임 흐름이 끝까지 동작하고, 두 플레이어에게 동일하고 설명 가능한 판정이 제공되는지 검증한다.

## 2. 출시 전 필수 조건

- 두 사용자가 매칭부터 결과까지 한 판을 완주할 수 있다.
- 차이점 3개와 모든 정답 영역이 정확히 교환된다.
- 서버 기준 타이머와 승패가 양쪽 화면에서 일치한다.
- 오답 페널티와 힌트가 중복 적용되지 않는다.
- 연결 및 서버 오류가 정의된 방식으로 종료된다.
- 심각한 보안, 데이터 손실, 진행 불가 문제가 없다.

## 3. 기능 테스트

### 매칭과 준비

- 정상적으로 상대를 찾아 같은 경기에 입장한다.
- 매칭 취소 후 로비로 돌아간다.
- 상대 미입장과 이미지 로드 실패가 안내된다.
- 양쪽에 같은 원본 이미지 버전이 제공된다.

### 차이점 제작

- 세 가지 제작 도구가 예상대로 표시된다.
- 차이점이 3개 미만이면 제출할 수 없다.
- 너무 작거나 겹치거나 경계를 벗어난 차이점이 거절된다.
- 추가, 수정, 삭제 후 등록 개수가 정확하다.
- 제출 후 편집할 수 없다.
- 제한시간 종료 시 자동 보충 또는 취소 정책이 적용된다.

### 차이점 찾기

- 정답 영역 선택 시 한 번만 인정된다.
- 이미 찾은 정답을 다시 선택해도 점수와 페널티가 변하지 않는다.
- 오답마다 남은 시간이 정확히 3초 감소한다.
- 힌트는 한 번만 사용되고 미발견 정답을 대상으로 한다.
- 상대의 발견 개수는 보이지만 위치는 노출되지 않는다.
- 서버 마감 이후 입력은 결과에 반영되지 않는다.

### 결과

- 전부 먼저 찾은 플레이어가 즉시 승리한다.
- 시간 종료 시 정답 수, 오답 수, 마지막 정답 시각 순으로 판정한다.
- 완전히 같은 조건은 무승부로 처리한다.
- 결과 상세와 실제 경기 기록이 일치한다.
- 재대전, 새 매칭, 로비, 신고 흐름이 동작한다.

## 4. 실시간 및 네트워크 테스트

자동화 완료: 동일 상태 지연 입력, 양쪽 동시 입력, 요청 ID 중복 전송, 제한시간 내 재접속, 유예시간 초과 기권, PostgreSQL 서버 재시작 복구.

- 빠른 연속 입력과 양쪽 동시 입력
- 지연, 패킷 순서 변경, 중복 전송
- 제작 제출 직전과 풀이 종료 직전 연결 끊김
- 10초 안의 재접속과 10초 초과 재접속
- 한쪽만 느린 네트워크를 사용하는 상황
- 새로고침 또는 여러 탭에서 같은 경기에 접근
- 서버 재시작 또는 실시간 연결 장애

결과는 클라이언트의 도착 순서가 아니라 서버의 유효한 처리 기록과 규칙에 따라 일관되어야 한다.

## 5. 화면 및 접근성 테스트

- 지원 대상 데스크톱·모바일 화면 크기
- 이미지 비율 변경과 확대 상태의 좌표 정확도
- 키보드 탐색과 포커스 표시
- 색각 이상 상태에서도 정답·오답 구분 가능 여부
- 타이머, 경고, 오류 메시지의 가독성
- 로딩과 연결 끊김 중 중복 입력 차단

## 6. 보안 및 악용 테스트

- 조작된 좌표, 상태 버전, 경기 ID 전송
- 다른 플레이어 경기로의 요청 시도
- 지나치게 빠른 클릭과 요청 반복
- 정답 좌표 또는 상대 제작 데이터의 조기 노출 여부
- 닉네임과 신고 설명의 비정상 입력
- 허용되지 않은 이미지 또는 제작 명령

## 7. 플레이테스트 질문

- 30초 안에 차이점 3개를 만들 수 있는가?
- 제작 도구와 제출 조건을 설명 없이 이해하는가?
- 상대의 문제를 어렵지만 공정하다고 느끼는가?
- 60초와 오답 3초 차감이 적절한가?
- 상대 진행도 표시가 긴장감을 높이는가?
- 경기 종료 후 다시 플레이하고 싶은가?

## 8. 결함 우선순위

- **치명적:** 경기 진행 불가, 잘못된 승패, 데이터 또는 정답 노출
- **높음:** 핵심 기능 실패, 재현 가능한 동기화 불일치
- **보통:** 우회 가능한 기능 또는 화면 문제
- **낮음:** 게임 결과에 영향 없는 표현과 미세한 시각 문제

치명적·높음 결함은 출시 전에 해결하고 동일 조건에서 재검증한다.
